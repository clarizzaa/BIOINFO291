# BIOINFO291 — Reproducible analysis project

Coursework repository for BIOINFO291 / CHEM291, *Practical Data Analysis in
Systems Biology* (UCLA). It is set up so that the **repository**, not a chat
transcript, is the record of the analysis: a reader with this repo and no
access to the conversation can rerun everything and get the same numbers and
the same figures.

**Working rules: [WORKSPACE.md](WORKSPACE.md).** Read that first.

## Layout

    data/raw/         original inputs, read-only, not tracked
    data/metadata/    source URLs, accessions, checksums, sample sheets
    data/processed/   derived data, regenerated by code, not tracked
    src/              reusable functions
    workflows/        numbered scripts: raw data -> results and figures
    configs/          every parameter, in YAML, including the random seed
    results/          tables and statistics
    figures/          generated plots
    reports/          write-ups and DECISIONS.md (the decision log)
    tests/            pytest checks
    environment/      per-step conda specs and lock files
    docs/             how this repo is driven inside Claude Science

## Analyses

### scRNA-seq immunotherapy tumour response (GSE120575)

Immune composition and CD8 T-cell state in 48 melanoma biopsies taken before
and during checkpoint blockade, from Sade-Feldman et al., *Cell* 2018.
Reproduces the course's worked example, with the experimental unit corrected
from the biopsy to the patient.

**Report: [reports/scrnaseq-immunotherapy.md](reports/scrnaseq-immunotherapy.md)**

    git clone https://github.com/clarizzaa/BIOINFO291.git
    cd BIOINFO291
    conda env create -f environment/env-scrna.yml
    conda activate scrna
    bash workflows/run_all.sh

That downloads ~127 MB from GEO on the first run, verifies it against the
checksums in [data/metadata/SOURCES.md](data/metadata/SOURCES.md), and
regenerates every table in `results/`, every figure in `figures/`, and the
report itself. It takes roughly three minutes on a laptop and needs about
2 GB of memory.

| Step | Does |
|---|---|
| `00_download_data.py` | fetch GSE120575, checksum it, make it read-only, register it |
| `01_build_anndata.py` | parse the matrix and clinical labels into an AnnData |
| `02_qc.py` | QC filters, with counts removed at each step |
| `03_cluster.py` | HVGs, PCA, Harmony over patients, Leiden, UMAP |
| `04_annotate.py` | label clusters as immune populations from marker panels |
| `05_composition.py` | confounding checks, then composition tests per patient |
| `06_pseudobulk_de.py` | pseudobulk DE and a cross-validated response signature |
| `07_report.py` | write the report from the generated results |

Each step is independently runnable and declares its inputs and outputs at
the top of the file. Checks on the repository's own rules:

    conda activate scrna && pytest -q

## Week 3 — statistical review

`docs/statistical-review.md` states the rules a paper's statistics are held to:
sixteen enforced (S1–S16) and seven reporting items (R1–R7), derived from
lecture 3. As with the figure contract, the rules have two halves that cite them
and never restate them — `skills/statistical-review/` runs a review, and
`agents/statistical-reviewer/` reaches a verdict without the ability to edit
anything.

A review takes a paper **and the data the paper was built from**: it reproduces
every reported statistic, recovers the experimental unit each test actually
counted, counts and corrects the family of tests, re-analyses at the defensible
unit, and states what survives. A paper whose deposit cannot be obtained is not
reviewed, because a blocking finding must be demonstrated by recomputation.

    python workflows/30_fetch_papers.py <slug>        # register paper + deposit
    python workflows/31_describe_deposit.py <slug>    # look before computing
    python workflows/32_recompute_wang2026.py         # reproduce + re-analyse
    python workflows/33_fig_wang2026.py               # review figures + sidecars

Reviews are in `reports/statistical_reviews/`.
